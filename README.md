# Bomberman 64

A matching decompilation of Hudson Soft's *Bomberman 64* (N64, 1997;
*Baku Bomberman* in Japan),
aimed at a PC port, native and WebAssembly, with online multiplayer over
WebRTC. You need your own ROM. None of the game's code or data is in this
repository.

Stage 2 is done: all three ROMs rebuild byte for byte from disassembled code
(boot code, main code, all 95 overlays) and inflated assets, recompressed
at build time. A shifted build, with every module's code and data moved,
plays the same as the original in an emulator. Nothing is decompiled yet. docs/ROADMAP.md has the plan,
and docs/NETPLAY.md the multiplayer design.

## ROMs

| version | file | code | sha1 |
| --- | --- | --- | --- |
| `us` | `baserom.us.z64` | `NBME` | `8a7648d8105ac4fc1ad942291b2ef89aeca921c9` |
| `eu` | `baserom.eu.z64` | `NBMP` | `01e50f41733994bf229bee3b3d8aa9fd46441175` |
| `jp` | `baserom.jp.z64` | `NBMJ` | `4813b147d552f72fdb0b306469bf9aa0f820fd5b` |

All three are 8 MiB, big-endian `.z64`, CIC 6102. `us` is the working
version; `jp` is *Baku Bomberman*, the Japanese release.

Not targets:

- `NHAJ`, sha1 `62f091b8b951238a7fb98459257ecc8a9095f6e9`, 16 MiB, is
  *Bomberman 64* (2001), a different, Japan-only game despite the title.

## Build

You need `mips-linux-gnu-` binutils, Python 3, a C compiler, `curl` and
`git`. On Debian/Ubuntu:

```
sudo apt install binutils-mips-linux-gnu build-essential python3-venv curl git
make setup                      # submodules, .env venv, IDO 5.3, the LZSS helper
make VERSION=us extract         # split baserom.us.z64 (sha1-checked first) into asm/ and assets/
make VERSION=us                 # rebuild it, sha1-checked
make VERSION=us lzss-check      # every compressed member recompresses exactly
make VERSION=us shift-check     # a shifted build against the original, in mupen64plus
```

`VERSION` is `us` (the default), `eu` or `jp`. `asm/` and `assets/` hold one
version at a time, so run `make clean` before you switch.

`shift-check` needs mupen64plus (2.6.0): the system's install (a
distribution package with the core and `mupen64plus-rsp-hle`), or the
[Linux bundle](https://github.com/mupen64plus/mupen64plus-core/releases)
unpacked somewhere, with `M64P_DIR` set to that directory. It runs
headless, from a blank save, with a scripted controller
(`tools/inputs/menus.txt`: mode and file select, the opening, the world
select and the first stage), and compares the modules' data at nine
checkpoints up to frame 24000. A second run (`tools/inputs/battle.<v>.txt`,
per version) plays battle mode against three CPU players for 18000 frames,
five or six matches, and compares at 13-15 checkpoints in the arenas and
result screens; it reaches `ovl_0B_03`, `ovl_17_01` and `ovl_0B_07`, which
the first run never loads (`make shift-check-battle` runs just that one,
about a minute). The game's random seed comes from the CPU's
cycle counter, which the shifted build's bigger DMAs change, so both ROMs
run with it pinned (`tools/shift_check.py` explains).

## Layout

| path | what |
| --- | --- |
| `bm64.<v>.yaml` | splat config of the code image, generated by `tools/layout.py <v>`; don't hand-edit |
| `bm64.<v>.sha1` | the ROM's sha1, what the build has to reproduce |
| `tools/layout.py` | reads the ROM's layout and writes the config; `--check` verifies it |
| `tools/assets.py` | archives to `assets/bankNN/` (inflated entries, manifests) and back; the code image |
| `tools/split.py` | runs splat (outside us, with the C files' us names read as the version's) |
| `tools/postsplit.py` | after splat: what it left as addresses becomes label-relative |
| `tools/vermap.py`, `vermap.<v>.txt` | where us's addresses are in eu and jp; extract renames those versions' names to us's |
| `tools/ld_fix.py` | splat's linker script with the ROM's fixed positions kept (and `SHIFT` pads) |
| `tools/rom.py` | the ROM from the code image and the archives |
| `tools/find_abs.py` | addresses in the linked code that have no relocation |
| `tools/shift_check.py`, `tools/emu_ram.py` | shifted vs original, run headless in mupen64plus |
| `tools/tas.py` | TASVideos' movies played headless, the game's progress reported and compared between ROMs (docs/TAS.md) |
| `tools/bizhawk_core.sh` | BizHawk 2.8's mupen64plus core built for Linux, a reference for `tas.py` |
| `tools/hudson_lzss.py` | Hudson's LZSS, both directions (`tools/src/hudson_lzss.c` is the fast encoder) |
| `tools/lzss_check.py` | round-trips every compressed member of a ROM |
| `tools/test_lzss.py` | ROM-free codec self-test (CI) |
| `tools/n64crc.py` | header checksum |
| `tools/get_ido.sh` | fetches decompals' IDO 5.3 static recompilation (pinned sha256) |
| `tools/{asm-differ,asm-processor,m2c,decomp-permuter}` | submodules |
| `docs/` | LAYOUT (ROM map, loaders, the code image), COMPRESSION, ROADMAP, NETPLAY |
